# ระบบประเมินโครงงาน 02739498 ปัญหาพิเศษ

หน้าเว็บ HTML/CSS/JavaScript บน GitHub Pages เชื่อม Google Apps Script และ Google Sheets

| ส่วน | คะแนน | สถานะ | ที่จัดเก็บ |
|---|---:|---|---|
| หัวข้อโครงงาน | 10 | เก็บแล้ว / ปิดรับคะแนน | Scores, Summary เดิม |
| อาจารย์ที่ปรึกษา | 50 | วางแผน ยังไม่เปิด | ยังไม่สร้าง |
| รายงานความก้าวหน้า | 20 | วางแผน ยังไม่เปิด | ยังไม่สร้าง |
| สอบวิพากษ์ | 20 | เปิดประเมิน | DefenseScores, DefenseSummary |

## ติดตั้งรุ่นสอบวิพากษ์

1. สำรอง Google Sheet เดิม แล้วแทนโค้ดใน Apps Script ด้วย `Code.gs` รุ่นนี้
2. ตรวจชีท `Committees`: A แผนการเรียน, B ห้องสอบ, C ชื่อกรรมการ, **D อีเมลบัญชี Google ของกรรมการ** ใส่อีเมลทุกแถวที่ได้รับมอบหมาย ชื่อของอีเมลเดียวกันควรตรงกันทุกแถว บัญชีเดียวกันสามารถมีหลายห้อง/แผนการเรียนได้
3. รัน **`setupDefenseSheets`** สร้างชีทใหม่และสูตรเฉลี่ย รันซ้ำได้โดยไม่ล้างคะแนนเดิม **ห้ามรัน `setupSheets` เพราะจะล้างชีทเดิม** และไม่ต้องรัน initializeStudents/initializeCommittees
4. ตรวจ OAuth Web Client ใน Google Cloud Console ให้ Authorized JavaScript origins มี origin ที่โฮสต์จริง เช่น `https://suriyapi.github.io` (ไม่ใส่ path ของ repository) ค่า Client ID ใน `app.js`, `dashboard.html`, `Code.gs` ต้องตรงกัน
5. Apps Script: Deploy → Manage deployments → Edit → New version → Deploy; Execute as Me และ Who has access Anyone ตัว API ตรวจ Google ID token และอีเมลก่อนอ่านข้อมูลนิสิต/เขียนคะแนน
6. อัปโหลด `index.html`, `styles.css`, `app.js`, `dashboard.html`, `dashboard.css` ไปที่โฟลเดอร์เดียวกันบน GitHub Pages หาก URL deployment เปลี่ยน ให้แก้ GAS_URL ใน app.js และ dashboard.html
7. ทดสอบด้วยบัญชีกรรมการจริง: เข้าใช้งาน → ค้นรหัสนิสิตที่ตรงห้อง → ให้คะแนน → ตรวจ DefenseScores และ DefenseSummary จากนั้นทดสอบอัปเดตคะแนนซ้ำและตรวจว่าคะแนน Scores เดิมยังอยู่

ระบบยังไม่ได้ deploy จาก workspace นี้ การทดสอบบัญชี Google และสิทธิ์ Apps Script จริงต้องทำหลังติดตั้ง โดยหน้าให้คะแนนจะปิดการใช้งานหาก backend ยังเป็นรุ่นเก่า

## การใช้งาน

- กรรมการต้องลงชื่อเข้าใช้ Google ด้วยอีเมลใน Committees ไม่มีช่องพิมพ์ชื่อแทนบัญชี
- เปิดหมวดสอบวิพากษ์เป็นค่าเริ่มต้น ค้นนิสิตด้วยรหัส 10 หลัก และให้คะแนนรายบุคคล 5 เกณฑ์
- กรรมการให้คะแนนได้เฉพาะห้อง/แผนการเรียนที่ได้รับมอบหมาย ตรวจทั้งหน้าเว็บและ backend หากนั่งแทน ให้ผู้ดูแลแก้การมอบหมายใน Committees ก่อน
- คะแนนดิบเป็นจำนวนเต็ม 0–4 น้ำหนัก 6, 3, 5, 2, 4 รวม 20 คะแนน เกณฑ์และคำอธิบายระดับโหลดจาก backend จุดเดียว
- บันทึกซ้ำใช้รหัสนิสิต + อีเมลที่ยืนยันแล้วเป็นกุญแจอัปเดต พร้อม lock ป้องกันการเขียนชนกัน
- เมื่อ token หมดอายุ ต้องเข้าสู่ระบบใหม่ หน้าให้คะแนนเก็บ token ในหน่วยความจำเท่านั้น
- แดชบอร์ดจำกัดบัญชีตาม DASHBOARD_ALLOWED_EMAIL และเลือกดูหัวข้อโครงงานหรือสอบวิพากษ์แยกกัน เก็บ token ใน sessionStorage ของแท็บ
- คะแนนเฉลี่ยใน DefenseSummary เป็นค่าเฉลี่ยคะแนนที่มีอยู่ ดูจำนวนผู้ประเมินควบคู่เพื่อยืนยันว่าครบตามห้องแล้ว ยังไม่ใช่คะแนนรวมทั้งวิชา

## CLO–PLO สำหรับสอบวิพากษ์

| เกณฑ์ | เชื่อมโยง | น้ำหนัก |
|---|---|---:|
| ระบบสารสนเทศและการแก้ปัญหา | CLO1 → PLO1 | 6 |
| เทคโนโลยี ฐานข้อมูล และโครงสร้างโปรแกรม | CLO2 → PLO2 | 3 |
| ความต้องการ การบูรณาการ และความปลอดภัย | CLO3 → PLO3 | 5 |
| ความรับผิดชอบและความซื่อสัตย์ | CLO4 → PLO6 | 2 |
| การสื่อสาร การทำงานร่วมกัน และจริยธรรม IT/AI | CLO5 → PLO4, PLO5 | 4 |

PLO6 ในการสอบนี้พิจารณาหลักฐานในโครงงาน การยืนยันผลลัพธ์ในสถานประกอบการต้องมีหลักฐานจากบริบทนั้นเพิ่มเติม

## แผนส่วนที่เหลือ

อาจารย์ที่ปรึกษา 50 คะแนน และรายงานความก้าวหน้า 20 คะแนน แสดงสัดส่วนในหน้าเว็บแล้ว แต่ยังไม่มีฟอร์ม เกณฑ์ ชีท หรือ API รับคะแนน ต้องกำหนดผู้ประเมิน สิทธิ์ รายละเอียดเกณฑ์ และวิธีรวมคะแนนก่อนเปิดใช้งาน
