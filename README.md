หน้าเว็บ HTML/CSS/JavaScript บน GitHub Pages เชื่อม Google Apps Script และ Google Sheets

| ส่วน | คะแนน | สถานะ | ที่จัดเก็บ |

## ติดตั้งรุ่นสอบวิพากษ์

1. สำรอง Google Sheet เดิม แล้วแทนโค้ดใน Apps Script ด้วย `Code.gs` รุ่นนี้
2. ตรวจชีท `Committees`: A แผนการเรียน, B ห้องสอบ, C ชื่อกรรมการ, **D อีเมลบัญชี Google ของกรรมการ** ใส่อีเมลทุกแถวที่ได้รับมอบหมาย ชื่อของอีเมลเดียวกันควรตรงกันทุกแถว บัญชีเดียวกันสามารถมีหลายห้อง/แผนการเรียนได้
3. รัน **`setupDefenseSheets`** สร้างชีทใหม่และสูตรเฉลี่ย รันซ้ำได้โดยไม่ล้างคะแนนเดิม **ห้ามรัน `setupSheets` เพราะจะล้างชีทเดิม** และไม่ต้องรัน initializeStudents/initializeCommittees
4. ตรวจ OAuth Web Client ใน Google Cloud Console ให้ Authorized JavaScript origins มี origin ที่โฮสต์จริง เช่น `https://suriyapi.github.io` (ไม่ใส่ path ของ repository) ค่า Client ID ใน `app.js`, `dashboard.html`, `Code.gs` ต้องตรงกัน
5. Apps Script: Deploy → Manage deployments → Edit → New version → Deploy; Execute as Me และ Who has access Anyone ตัว API ตรวจ Google ID token และอีเมลก่อนอ่านข้อมูลนิสิต/เขียนคะแนน
6. อัปโหลด `index.html`, `styles.css`, `app.js`, `dashboard.html`, `dashboard.css`, `reference.css`, `responsive.css`, `boot.js`, `ui.js`, `icons.svg` ไปที่โฟลเดอร์เดียวกันบน GitHub Pages หาก URL deployment เปลี่ยน ให้แก้ GAS_URL ใน app.js และ dashboard.html
7. ทดสอบด้วยบัญชีกรรมการจริง: เข้าใช้งาน → ค้นรหัสนิสิตที่ตรงห้อง → ให้คะแนน → ตรวจ DefenseScores และ DefenseSummary จากนั้นทดสอบอัปเดตคะแนนซ้ำและตรวจว่าคะแนน Scores เดิมยังอยู่

ระบบยังไม่ได้ deploy จาก workspace นี้ การทดสอบบัญชี Google และสิทธิ์ Apps Script จริงต้องทำหลังติดตั้ง โดยหน้าให้คะแนนจะปิดการใช้งานหาก backend ยังเป็นรุ่นเก่า

## การใช้งาน

- กรรมการต้องลงชื่อเข้าใช้ Google ด้วยอีเมลใน Committees ไม่มีช่องพิมพ์ชื่อแทนบัญชี
- หลังเข้าสู่ระบบ เปิดภาพรวมงานของฉัน ดูงานค้างและเลือกรายชื่อนิสิตที่ได้รับมอบหมาย ค้นด้วยชื่อ รหัส หรือหัวข้อได้
- ให้คะแนนรายบุคคล 15 ข้อย่อยใน 5 ด้าน ตรวจทานชื่อนิสิตและคะแนนในหน้าต่างตรวจสอบก่อนยืนยันส่ง คะแนนเดิมเปิดจากรายชื่อหรือประวัติเพื่อแก้ไขได้
- กรรมการให้คะแนนได้เฉพาะห้อง/แผนการเรียนที่ได้รับมอบหมาย ตรวจทั้งหน้าเว็บและ backend หากนั่งแทน ให้ผู้ดูแลแก้การมอบหมายใน Committees ก่อน
- คะแนนดิบรายข้อเป็นจำนวนเต็ม 0–4 รวม 15 ข้อ น้ำหนักย่อยรวมต่อด้านเป็น 6, 3, 5, 2, 4 รวม 20 คะแนน เกณฑ์และคำอธิบายระดับโหลดจาก backend จุดเดียว
- บันทึกซ้ำใช้รหัสนิสิต + อีเมลที่ยืนยันแล้วเป็นกุญแจอัปเดต พร้อม lock ป้องกันการเขียนชนกัน
- เมื่อ token หมดอายุ ต้องเข้าสู่ระบบใหม่ หน้าให้คะแนนเก็บ token ใน sessionStorage ของแท็บเพื่อกลับเข้าใช้งานหลังรีเฟรช และล้างเมื่อออกจากระบบ
- แดชบอร์ดจำกัดบัญชีตาม DASHBOARD_ALLOWED_EMAIL และเลือกดูหัวข้อโครงงานหรือสอบวิพากษ์แยกกัน เก็บ token ใน sessionStorage ของแท็บ
- คะแนนเฉลี่ยใน DefenseSummary เป็นค่าเฉลี่ยคะแนนที่มีอยู่ ดูจำนวนผู้ประเมินควบคู่เพื่อยืนยันว่าครบตามห้องแล้ว ยังไม่ใช่คะแนนรวมทั้งวิชา

### รูปแบบตามภาพอ้างอิง Verdana Health

แถบเมนูสีเทาอ่อน ช่องค้นหาด้านบน การ์ดสถิติ 4 ใบ กราฟรายห้อง กราฟวงกลม และตารางสถานะนิสิต ใช้ข้อมูลจริงของกรรมการที่เข้าสู่ระบบ ไม่มีตัวเลขแนวโน้มสมมติ กราฟความคืบหน้าเป็นสถานะปัจจุบัน ไม่ใช่ประวัติย้อนหลัง

ช่องค้นหาด้านบนพาไปผลลัพธ์ในรายชื่อนิสิตเมื่อกด Enter และปุ่มดาวน์โหลดส่งออกคะแนนสอบวิพากษ์ของตนเองเป็น CSV ภาษาไทย ปุ่มนี้เปิดใช้งานเมื่อมีคะแนนที่บันทึกแล้วเท่านั้น

### Mobile / Tablet และการทดสอบ UI

- จอไม่เกิน 1100 px ใช้ hamburger drawer พร้อมแอนิเมชัน ล็อกการเลื่อนพื้นหลัง รองรับ Escape และวนโฟกัสคีย์บอร์ดภายในเมนู
- รายชื่อบนมือถือ/แท็บเล็ตเปลี่ยนเป็นการ์ด แถบคะแนนรวมปรับขนาดและเว้นขอบปลอดภัยของอุปกรณ์
- ช่องเลือกห้อง/หมวดใช้ listbox ร่วมกัน เพื่อให้ฟอนต์ Noto Sans Thai สม่ำเสมอ เลือกได้ด้วยลูกศร Home/End Enter และ Escape
- Hover ใช้กับอุปกรณ์ที่มีเมาส์ และรองรับ prefers-reduced-motion

ทดสอบด้วย `npm ci` แล้ว `npm run test:ui` และ `npm run test:ui:touch` สำหรับการแตะบนอุปกรณ์สัมผัส (ใช้ Google Chrome ที่ติดตั้งในเครื่อง) หรือรัน `npx playwright install chromium` และ `UI_BROWSER_CHANNEL=bundled npm run test:ui` เพื่อใช้ Chromium ของ Playwright

การทดสอบ UI ใช้บัญชีและข้อมูลจำลอง ไม่อ่านหรือบันทึกคะแนนบนระบบจริง ภาพตรวจสอบจะอยู่ในโฟลเดอร์ `special-problem-ui-tests` ใต้ temporary directory ของเครื่อง

## เกณฑ์สอบวิพากษ์รุ่น 15 ข้อย่อย

เวอร์ชัน `defense-v2-15` แบ่งเป็น 5 ด้าน โดยทุกข้อให้คะแนนดิบ 0–4 และคำนวณ `(คะแนนดิบ / 4) × น้ำหนักข้อ`

| ด้าน | จำนวนข้อ | น้ำหนักย่อย | รวม |
|---|---:|---|---:|
| ระบบสารสนเทศและการแก้ปัญหา | 3 | 2 + 2 + 2 | 6 |
| เทคโนโลยี ฐานข้อมูล และโครงสร้างโปรแกรม | 3 | 1 + 1 + 1 | 3 |
| ความต้องการ การบูรณาการ และความปลอดภัย | 3 | 2 + 2 + 1 | 5 |
| ความรับผิดชอบและความซื่อสัตย์ | 2 | 1 + 1 | 2 |
| การสื่อสาร การทำงานร่วมกัน และจริยธรรม IT/AI | 4 | 1 + 1 + 1 + 1 | 4 |
| **รวม** | **15** | | **20** |

ดูคำถาม หลักฐาน และคำอธิบายคะแนนทั้งหมดใน [เกณฑ์ฉบับละเอียด](docs/DEFENSE_RUBRIC.md) หรือหน้าคู่มือในเว็บ

- หน้าให้คะแนนเปิดประเมินทีละด้าน พร้อมจำนวนข้อที่ตอบแล้วและปุ่มไปด้านถัดไป ต้องตอบครบ 15 ข้อก่อนตรวจทานและยืนยัน
- คะแนนเดิมแบบ 5 ด้านยังแสดงในภาพรวมและประวัติ ไม่มีการคาดเดาหรือเติมคำตอบรายข้อจากคะแนนเดิม หากต้องการแก้ไขรายการเก่า ต้องประเมินใหม่ครบทั้ง 15 ข้อก่อนยืนยันแทนคะแนนเดิม
- การบันทึกรุ่นใหม่เพิ่มคอลัมน์ N เป็นเวอร์ชัน และ O:AC เป็นคะแนนดิบรายข้ออัตโนมัติเมื่อบันทึกครั้งแรก ไม่ต้องรัน setupSheets หรือสร้างชีทใหม่
- คอลัมน์ G:K เป็นคะแนนดิบเทียบเท่ารายด้าน 0–4 ซึ่งอาจมีทศนิยม ส่วน L ยังคงเป็นคะแนนรวมเต็ม 20 และ M เป็นอีเมล สูตร Summary และแดชบอร์ดจึงอ่านคะแนนรวมตำแหน่งเดิมได้
- ดาวน์โหลด CSV จะแสดงคะแนนย่อยและเวอร์ชันด้วย รายการเก่าที่ไม่มีรายละเอียดจะเว้นช่องคะแนนย่อยว่าง
- ทดสอบการคำนวณด้วย `npm test` และขั้นตอนประเมิน 15 ข้อด้วย `npm run test:questions`

## การเข้าสู่ระบบบน Safari และกราฟโต้ตอบ

หลังยืนยันบัญชี ระบบแสดงสถานะกำลังโหลดและเลื่อนไปด้านบน หากเครือข่ายล้มเหลวหรือเกิน 25 วินาทีจะแสดงปุ่มลองใหม่ หากส่วนประกอบ JavaScript โหลดไม่ครบจะแสดงหน้ากู้คืนและปุ่มโหลดหน้าใหม่ การกลับจาก bfcache จะปลดสถานะเมนู/พื้นหลังที่ค้างอยู่ มี fallback สำหรับ replaceChildren และ MediaQueryList รุ่นเก่า และไม่ใช้ค่า scroll behavior แบบ instant

กราฟห้องและวงกลมในหน้ากรรมการเลือกตัวกรองร่วมกันได้ ตารางด้านล่างจะเปลี่ยนตามห้อง/สถานะที่เลือก ปุ่มเปิดรายชื่อจะส่งตัวกรองไปหน้ารายชื่อนิสิต พร้อมปุ่มล้างตัวกรอง Tooltip รองรับเมาส์และคีย์บอร์ด ส่วนบนมือถือใช้การแตะและแสดงสถานะการเลือกในหน้า

แดชบอร์ดผู้ดูแลแตะกราฟห้องเพื่อกรองรายชื่อ แตะกราฟรายเกณฑ์เพื่อดูคะแนนเทียบตามน้ำหนัก และแตะแถบกรรมการเพื่อเปิดรายชื่อที่ประเมินแล้ว/ยังค้าง

- `npx playwright install webkit` เตรียม WebKit สำหรับการทดสอบ
- `npm run test:safari` ทดสอบหน้าล็อกอินด้วย WebKit จำลอง iPhone รวมความล้มเหลวของเครือข่าย/timeout/สคริปต์ และการกู้คืนหน้าจอ
- `npm run test:charts` ทดสอบกราฟบน Chrome และ WebKit แบบสัมผัส

OAuth และข้อมูลส่วนตัวในการทดสอบใช้ข้อมูลจำลอง การทดสอบ WebKit ไม่ใช่การตรวจบน iPhone ของผู้ใช้โดยตรง
