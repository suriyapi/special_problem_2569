# อาจารย์ที่ปรึกษา 50 คะแนน — advisor-v1-15

ประเมินรายบุคคลจากหลักฐานตลอดภาคเรียน ไม่ใช้เฉพาะการนำเสนอวันสอบ ทุกข้อให้ระดับจำนวนเต็ม 0–4 และคิด `(ระดับ / 4) × น้ำหนักข้อ` รวมไม่เกิน 50 คะแนน คำอธิบายระดับเฉพาะข้ออยู่ใน `ADVISOR_CRITERIA` ใน Code.gs และเปิดอ่านได้ในแบบประเมิน

| ด้าน | เชื่อมโยง | ข้อและน้ำหนัก | รวม |
|---|---|---|---:|
| พัฒนาระบบ | CLO1 → PLO1 | ฟังก์ชันหลัก 4 · ความถูกต้อง 3 · แก้ปัญหาระหว่างพัฒนา 3 | 10 |
| เทคโนโลยีและข้อมูล | CLO2 → PLO2 | เลือกเทคโนโลยี 4 · โครงสร้างจัดเก็บข้อมูล 3 · โครงสร้างโปรแกรม/เข้าถึงข้อมูล 3 | 10 |
| บูรณาการตามความต้องการ | CLO3 → PLO3 | ความต้องการสู่ผลงาน 5 · รวมระบบและทดสอบ 5 · ความปลอดภัยและข้อมูล 5 | 15 |
| รับผิดชอบ | CLO4 → PLO6 | แผนและสิ่งส่งมอบ 5 · งานตนเองและรายงานตามจริง 5 | 10 |
| สื่อสารและจรรยาบรรณ | CLO5 → PLO4, PLO5 | นำเสนอ 1 · ประสานงาน 1 · ปรับปรุงจากข้อเสนอแนะ 1 · จรรยาบรรณ IT/AI 2 | 5 |
| **รวม** | | **15 ข้อ** | **50** |

ระดับ 4 ทำได้ครบถูกต้อง มีเหตุผลและหลักฐานชัดเจน; 3 ตามข้อกำหนดมีข้อบกพร่องเล็กน้อย; 2 ทำได้บางส่วนยังต้องแก้สาระสำคัญ; 1 มีหลักฐานเบื้องต้นแต่ยังไม่บรรลุส่วนใหญ่; 0 ไม่บรรลุหรือไม่มีหลักฐานหลังถึงกำหนดประเมิน **ยังไม่ประเมินเป็นช่องว่าง แยกจากระดับ 0**

การใช้ AI ไม่ถูกหักคะแนนโดยตัวมันเอง พิจารณาการเปิดเผย การตรวจสอบ การอ้างอิงและการรักษาข้อมูล PLO6 ส่วนนี้แสดงความรับผิดชอบในบริบทโครงงาน การยืนยันการปฏิบัติงานในสถานประกอบการต้องใช้หลักฐานเพิ่มเติม

## ขั้นตอนใช้งาน

เข้าสู่ระบบ Google → เมนู **อาจารย์ที่ปรึกษา** → เลือกนิสิต → บันทึกหลักฐาน/คะแนนร่างระหว่างภาคเรียน → ประเมินครบ 15 ข้อ → ตรวจสอบ → ยืนยันคะแนน

- บันทึกร่างได้แม้ตอบไม่ครบ เปิดจากอุปกรณ์อื่นได้หลังบันทึกลงเซิร์ฟเวอร์
- เลือกร่างที่ใหม่กว่าคะแนนยืนยันมาแก้ไข หากไม่มีร่างใหม่ใช้คะแนนยืนยันล่าสุด
- คะแนนร่างไม่รวมในสรุป และไม่แทนคะแนนยืนยันเดิม
- แต่ละครั้งที่ยืนยัน อัปเดตแถวเดิมของรหัสนิสิต + อีเมลที่ยืนยันแล้ว พร้อมเก็บประวัติรายละเอียดเดิมใน audit
- บันทึกการให้คำปรึกษาแยกจากคะแนน ระบุวันที่ งาน หลักฐาน ปัญหา ข้อเสนอแนะ และนัดครั้งถัดไป ไม่เฉลี่ยคะแนนร่างแต่ละครั้ง
- งานกลุ่มใช้หลักฐานระบบร่วมกันได้ แต่ประเมินความรับผิดชอบ สื่อสาร และจรรยาบรรณแยกคน
- ดาวน์โหลด CSV เฉพาะคะแนนยืนยันของตนเองได้ ผู้ดูแลเลือกหมวดอาจารย์ที่ปรึกษาใน dashboard ได้

## ผูกสิทธิ์ที่ปรึกษา

สิทธิ์ที่ปรึกษาเป็น **รายนิสิต** แยกจากห้องสอบใน Committees

ชีท `Advisors`: A **รหัสนิสิต**, B **อีเมลที่ปรึกษา**, C **ชื่อที่ปรึกษา**

ใส่หนึ่งแถวต่อรหัสนิสิตและอีเมล หากมีที่ปรึกษาหลายคนใส่หลายแถวได้ และสรุปเฉลี่ยเฉพาะคะแนนยืนยันที่มีอยู่เต็ม 50 คะแนน ต้องตรวจจำนวนที่ยืนยันเทียบจำนวนที่รับผิดชอบก่อนใช้คะแนนสรุป

หากนิสิตมีแถวใน Advisors ระบบใช้การมอบหมายจากชีทนี้เท่านั้น แถวที่ยังไม่มีอีเมลจะไม่ให้สิทธิ์ใคร จึงใช้ระงับการจับคู่ชื่อเดิมได้ด้วย

สำหรับนิสิตที่ไม่มีแถวใน Advisors ระบบรองรับข้อมูลเดิม: ชื่อที่ปรึกษาใน Students คอลัมน์ E ต้องตรงกับชื่อเต็มใน Committees คอลัมน์ C หลังตัดช่องว่างหัวท้าย และชื่อนั้นต้องผูกกับอีเมลเดียวในคอลัมน์ D เท่านั้น ไม่จับคู่ชื่อบางส่วนและไม่เดาอีเมล

ที่ปรึกษาที่ไม่ได้เป็นกรรมการห้องสอบเข้าสู่ระบบผ่าน Advisors ได้ แต่ไม่ได้สิทธิ์ให้คะแนนสอบวิพากษ์เพิ่ม

## ที่จัดเก็บและการติดตั้ง

อัปเดต Code.gs ใน Apps Script และ deployment เดิมก่อนเผยแพร่ `index.html`, `app.js`, `advisor.js`, `advisor.css`, `boot.js` และ `dashboard.html` รุ่นใหม่ ชีทใหม่สร้างด้วย `setupAdvisorSheets` ซึ่งรันซ้ำได้โดยไม่ล้างข้อมูลเดิม การบันทึกครั้งแรกก็สร้างชีทที่เกี่ยวข้องให้อัตโนมัติ

| ชีท | ข้อมูล |
|---|---|
| Advisors | การมอบหมายรายนิสิตและอีเมล |
| AdvisorScores | คะแนนยืนยันล่าสุดของแต่ละนิสิตและที่ปรึกษา |
| AdvisorDrafts | ร่างล่าสุด ไม่ใช่คะแนนรายวิชา |
| AdvisorConsultations | บันทึกปรึกษาแยกแต่ละครั้ง |
| AdvisorAudit | ประวัติคะแนนย่อย หลักฐาน หมายเหตุและเวลาที่บันทึก |

AdvisorScores / AdvisorDrafts: A เวลา, B รหัสนิสิต, C ชื่อ, D ห้อง, E แผน, F ชื่อผู้ประเมิน, G:K ระดับเทียบเท่าแต่ละด้าน 0–4, L คะแนนเต็ม 50 (**ร่างเว้นว่าง**), M อีเมล, N เวอร์ชัน, O:AC คะแนนดิบ 15 ข้อ, AD หลักฐาน JSON, AE หมายเหตุ

API ตรวจ Google token และการมอบหมายใหม่ทุกครั้ง คำนวณคะแนนบนเซิร์ฟเวอร์ และล็อกการเขียน ชีทที่มีโครงสร้างอื่นอยู่แล้วจะถูกปฏิเสธก่อนเขียน ไม่แก้ Scores / DefenseScores หรือคะแนนส่วนอื่น
