# สรุปคะแนนรายวิชา 100 คะแนน

หน้า `summary.html` อ่านข้อมูลได้เฉพาะ **ผู้จัดการรายวิชา suriya.p@ku.th** ตรวจ Google ID token และอีเมลบนเซิร์ฟเวอร์ทุกครั้ง

| ส่วน | คะแนนเต็ม | แหล่งข้อมูล |
|---|---:|---|
| หัวข้อโครงงาน | 10 | Scores |
| อาจารย์ที่ปรึกษา | 50 | AdvisorScores |
| รายงานความก้าวหน้า | 20 | ProgressScores |
| สอบวิพากษ์ | 20 | DefenseScores |
| **รวม** | **100** | |

เฉลี่ยคะแนนยืนยันล่าสุดของผู้ประเมินที่ได้รับมอบหมายภายในแต่ละส่วน ปัดทศนิยม 2 ตำแหน่งต่อส่วน แล้วบวกทั้งสี่ส่วน ไม่คูณน้ำหนักซ้ำเพราะคะแนนต้นทางเป็น 10, 50, 20, 20 อยู่แล้ว

## ความครบถ้วน

- แสดงคะแนนรวมเต็ม 100 เมื่อนิสิตปิดคะแนนครบทุกส่วนและไม่มีรายการที่ต้องตรวจสอบ โดยหัวข้อโครงงานรองรับการอนุมัติข้อยกเว้น 2/3 คนตามเงื่อนไขด้านล่าง
- ช่องว่างเป็น **รอข้อมูล** ไม่ใช่คะแนน 0 คะแนน 0 ที่ยืนยันและมีรายละเอียดถูกต้องนับได้ตามจริง
- คะแนนเฉลี่ยรายส่วนที่มีผู้ประเมินเพียงบางคนแสดงพร้อมจำนวนที่ได้/จำนวนที่ต้องครบ ยังไม่ใช้แสดงคะแนนรวม
- ค่าเฉลี่ยรวมของรายวิชาคิดเฉพาะนิสิตที่ข้อมูลครบทั้ง 4 ส่วน
- คะแนนร่าง บันทึกการปรึกษา และ audit ไม่ถูกนำมารวม
- เป็นผลสรุปจากข้อมูลที่โหลดล่าสุด ยังไม่มีการแปลงเป็นเกรดตัวอักษรหรือส่งผลออกไปยังระบบทะเบียน

## ผู้ประเมินและข้อมูลเดิม

หัวข้อและสอบวิพากษ์ใช้กรรมการปัจจุบันใน Committees ตามห้อง/แผนการเรียน ที่ปรึกษาใช้การมอบหมายรายนิสิตตามกติกาของ Advisors และการจับคู่ชื่อเดิมแบบไม่กำกวม ส่วนความก้าวหน้ามีผู้จัดการคนเดียวต่อคน

หากมีการเปลี่ยนกรรมการหลังประเมินหัวข้อ ต้องตรวจการมอบหมายและข้อมูลเดิมก่อนถือว่าคะแนนครบ ระบบไม่เดารายชื่อกรรมการในอดีต

- รหัสนิสิตซ้ำนับครั้งเดียวและแจ้งเตือน
- รายการซ้ำของนิสิตและผู้ประเมินคนเดียวใช้เวลาบันทึกล่าสุด กรณีเวลาเท่ากันใช้แถวหลังสุด ไม่เฉลี่ยคะแนนเก่าซ้ำ
- หากรายการล่าสุดผิดรูปแบบ จะแสดงให้ตรวจสอบ ไม่ย้อนกลับไปใช้คะแนนเก่าเงียบ ๆ
- คะแนนหัวข้อเดิมที่ไม่มีอีเมลรองรับการจับคู่ชื่อเต็มกับกรรมการที่ได้รับมอบหมายเพียงคนเดียว
- คะแนนสอบวิพากษ์ที่ไม่มีอีเมลแสดงสถานะต้องตรวจสอบตัวตนก่อนแสดงคะแนนรวม
- อีเมลที่ไม่ได้รับมอบหมายไม่ถูกนำมาคิด และแจ้งรายการที่ถูกตัดออกให้ผู้จัดการตรวจ
- ตรวจคะแนนรวมกับคะแนนย่อย และตรวจเวอร์ชันเกณฑ์ รายการผิดหรือว่างไม่นับเป็นคะแนน 0
- แผนความก้าวหน้าที่แก้ภายหลังไม่เปลี่ยนคะแนนยืนยันเดิม การสรุปอ่านคะแนนยืนยันตามเดิม

## ใช้งาน

เข้าสู่ระบบ → ดูจำนวนข้อมูลครบ/ยังขาด → กรองด้วยชื่อ รหัส หัวข้อ ห้อง สถานะ หรือส่วนที่ยังไม่ครบ → เปิดรายละเอียดเพื่อดูรายชื่อผู้ประเมินและรายการที่ขาด

แถบความครบถ้วนรายส่วนกดเพื่อกรองนิสิตที่ยังไม่ครบได้ ตารางเปลี่ยนเป็นการ์ดบนมือถือและแท็บเล็ตจอเล็ก เรียงคะแนนรวมได้โดยรายการรอข้อมูลอยู่ท้ายเสมอ

CSV ดาวน์โหลดตามตัวกรองทุกหน้า มีคะแนนแต่ละส่วน จำนวนผู้ประเมินที่มี/ต้องครบ คะแนนรวม และสถานะ ช่องคะแนนที่ยังไม่มีและคะแนนรวมที่ยังไม่ครบเว้นว่าง แยกจากเลข 0 และป้องกันข้อความที่อาจถูกอ่านเป็นสูตร

API `getCourseSummary` อ่านสรุปอย่างเดียว ส่วนหน้าสรุปมีคำสั่งให้ผู้จัดการตั้งวันหมดเขต อนุมัติ และเพิกถอนข้อยกเว้น โดยบันทึกแยกจากคะแนนต้นทาง กดรีเฟรชเพื่ออ่านคะแนนล่าสุด

## ทดสอบ

`npm test` ตรวจสิทธิ์ การเฉลี่ย/รวม ความครบถ้วน คะแนน 0 รายการซ้ำ ข้อมูลผิด และการคงข้อมูลต้นทาง

`npm run test:summary` ทดสอบ Chrome และ WebKit จำลองมือถือ รวมการเข้าสู่ระบบ ตัวกรอง รายละเอียด CSV แบ่งหน้า กราฟ ขนาด 320–1440 px การลองใหม่ และการล้างข้อมูลเมื่อเปลี่ยนบัญชี โดยใช้ข้อมูลจำลอง

## กรณีกรรมการหัวข้อประเมินไม่ครบหลังหมดกำหนด

ใช้เฉพาะ **หัวข้อโครงงาน 10 คะแนน** ผู้จัดการ **suriya.p@ku.th** อนุมัติเป็นรายนิสิต ระบบไม่อนุมัติอัตโนมัติเมื่อเลยวันหมดเขต

| คะแนนที่ถูกต้อง | การปิดคะแนน |
|---|---|
| 3/3 คน | ใช้ค่าเฉลี่ยทั้งสามคนตามปกติ |
| 2/3 คน | หลังหมดกำหนด ผู้จัดการอนุมัติใช้ค่าเฉลี่ยสองคนได้ โดยต้องมีเหตุผล |
| 0/3 หรือ 1/3 คน | ยังปิดด้วยข้อยกเว้นนี้ไม่ได้ ต้องประเมินเพิ่มเติม |

ตัวอย่าง 8 และ 9 คะแนน: `(8+9)/2 = 8.50/10` คงคะแนนเต็ม 10 และคงจำนวนผู้ประเมินจริง **2/3** ไม่มีการเติมคะแนน 0 หรือแสดงเป็น 3/3

### ขั้นตอนผู้จัดการ

1. เปิดหน้าสรุป 100 คะแนน และเปิด **กำหนดประเมินหัวข้อและการปิดคะแนน 2/3 คน**
2. ระบุวันสิ้นสุดตามกำหนดจริงและบันทึก วันหมดเขตสิ้นสุดเวลา 23:59:59.999 ตามเวลาไทย วันเริ่มต้นเว้นว่างไว้ให้ผู้จัดการระบุ
3. หลังสิ้นกำหนด เปิดรายละเอียดนิสิต หัวข้อที่มีคะแนนถูกต้อง 2 จากกรรมการ 3 คนและไม่มีรายการต้องตรวจสอบจะแสดงปุ่มอนุมัติ
4. ตรวจคะแนนเฉลี่ย รายชื่อที่ยังขาด และวันหมดเขต ระบุเหตุผล แล้วกดยืนยันอนุมัติ
5. สถานะแสดง **อนุมัติข้อยกเว้น** พร้อมเหตุผล อีเมลผู้อนุมัติ และเวลา หากส่วนอื่นครบแล้วจึงแสดงคะแนนรวม 100 คะแนน

กรณีกรรมการสองคนตามการมอบหมายอยู่แล้ว หรือมีแถวคะแนนผิดรูปแบบ ไม่นำกติกา 2/3 มาใช้แทนการตรวจข้อมูล

### การเปลี่ยนแปลงภายหลัง

- ผู้จัดการเพิกถอนข้อยกเว้นได้โดยระบุเหตุผล หากผู้ประเมินยังไม่ครบ ส่วนหัวข้อจะกลับมารอข้อมูล
- หากกรรมการคนที่สามมีคะแนนถูกต้องภายหลัง ใช้ค่าเฉลี่ยครบสามคนตามปกติ และเก็บการอนุมัติเดิมเป็นประวัติ
- คะแนนสองคน การมอบหมาย หรือกำหนดประเมินที่เปลี่ยนหลังอนุมัติ ทำให้ข้อยกเว้นเดิมต้องตรวจสอบใหม่ ไม่ปิดคะแนนด้วยผลอนุมัติที่อ้างอิงข้อมูลเก่า
- การอนุมัติจากหน้าจอที่เปิดค้างไว้จะถูกปฏิเสธหากข้อมูลหรือการตัดสินใจจากอีกแท็บเปลี่ยนไป
- คำขอเดิมที่ส่งซ้ำหลังเครือข่ายขัดข้องไม่เพิ่มการตัดสินใจซ้ำ กรณีไม่แน่ใจว่าบันทึกแล้วให้รีเฟรชตรวจสอบ
- ข้อยกเว้นนี้ไม่เปลี่ยนคะแนนของกรรมการที่เก็บไว้ใน Scores และไม่เปลี่ยนสิทธิ์หรือเกณฑ์ของส่วนอื่น

### ที่จัดเก็บ

`ProposalClosurePolicy` เก็บประวัติวันหมดเขต รุ่นกำหนด ผู้จัดการ และหมายเหตุ

`ProposalClosureDecisions` เก็บการอนุมัติ/เพิกถอนเป็นประวัติ พร้อมเหตุผล ผู้จัดการ เวลา ค่าเฉลี่ย และสำเนาคะแนนกับการมอบหมายที่ใช้พิจารณา ชีทจะสร้างเมื่อมีการบันทึกครั้งแรก การอนุมัติไม่ได้ทำอัตโนมัติจากการติดตั้ง

CSV แสดงสถานะข้อยกเว้น เหตุผล ผู้ตัดสินใจ เวลาตัดสินใจ วันหมดเขต และจำนวนผู้ประเมินจริง ตัวกรองข้อยกเว้นแสดงนิสิตที่หัวข้อได้รับอนุมัติ แม้ส่วนอื่นจะยังรอคะแนน

ทดสอบเงื่อนไขและสิทธิ์ด้วย `npm test` และขั้นตอนบน Chrome/WebKit ด้วย `npm run test:closure` ใช้ข้อมูลจำลอง ไม่อนุมัติคะแนนนิสิตจริงจากการทดสอบ
