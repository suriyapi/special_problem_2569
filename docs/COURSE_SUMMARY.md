# สรุปคะแนนรายวิชา 100 คะแนน

หน้า `summary.html` อ่านข้อมูลได้เฉพาะ **ผู้จัดการรายวิชา suriya.p@ku.th** ตรวจ Google ID token และอีเมลบนเซิร์ฟเวอร์ทุกครั้ง

| ส่วน | คะแนนเต็ม | แหล่งข้อมูล |
|---|---:|---|
| หัวข้อโครงงาน | 10 | Scores |
| อาจารย์ที่ปรึกษา | 50 | AdvisorScores |
| รายงานความก้าวหน้า | 20 | ProgressScores |
| สอบวิพากษ์ | 20 | DefenseScores |
| **รวม** | **100** | |

เฉลี่ยคะแนนยืนยันล่าสุดของผู้ประเมินที่ได้รับมอบหมายภายในแต่ละส่วน ปัดทศนิยม 2 ตำแหน่งต่อส่วน แล้วบวกทั้งสี่ส่วน ไม่คูณน้ำหนักซ้ำเพราะคะแนนต้นทางเป็น 10, 50, 20, 20 อยู่แล้ว

## ความครบถ้วน

- แสดงคะแนนรวมเต็ม 100 เมื่อนิสิตมีผู้ประเมินครบทุกส่วนและไม่มีรายการที่ต้องตรวจสอบ
- ช่องว่างเป็น **รอข้อมูล** ไม่ใช่คะแนน 0 คะแนน 0 ที่ยืนยันและมีรายละเอียดถูกต้องนับได้ตามจริง
- คะแนนเฉลี่ยรายส่วนที่มีผู้ประเมินเพียงบางคนแสดงพร้อมจำนวนที่ได้/จำนวนที่ต้องครบ ยังไม่ใช้แสดงคะแนนรวม
- ค่าเฉลี่ยรวมของรายวิชาคิดเฉพาะนิสิตที่ข้อมูลครบทั้ง 4 ส่วน
- คะแนนร่าง บันทึกการปรึกษา และ audit ไม่ถูกนำมารวม
- เป็นผลสรุปจากข้อมูลที่โหลดล่าสุด ยังไม่มีการแปลงเป็นเกรดตัวอักษรหรือส่งผลออกไปยังระบบทะเบียน

## ผู้ประเมินและข้อมูลเดิม

หัวข้อและสอบวิพากษ์ใช้กรรมการปัจจุบันใน Committees ตามห้อง/แผนการเรียน ที่ปรึกษาใช้การมอบหมายรายนิสิตตามกติกาของ Advisors และการจับคู่ชื่อเดิมแบบไม่กำกวม ส่วนความก้าวหน้ามีผู้จัดการคนเดียวต่อคน

หากมีการเปลี่ยนกรรมการหลังประเมินหัวข้อ ต้องตรวจการมอบหมายและข้อมูลเดิมก่อนถือว่าคะแนนครบ ระบบไม่เดารายชื่อกรรมการในอดีต

- รหัสนิสิตซ้ำนับครั้งเดียวและแจ้งเตือน
- รายการซ้ำของนิสิตและผู้ประเมินคนเดียวใช้เวลาบันทึกล่าสุด กรณีเวลาเท่ากันใช้แถวหลังสุด ไม่เฉลี่ยคะแนนเก่าซ้ำ
- หากรายการล่าสุดผิดรูปแบบ จะแสดงให้ตรวจสอบ ไม่ย้อนกลับไปใช้คะแนนเก่าเงียบ ๆ
- คะแนนหัวข้อเดิมที่ไม่มีอีเมลรองรับการจับคู่ชื่อเต็มกับกรรมการที่ได้รับมอบหมายเพียงคนเดียว
- คะแนนสอบวิพากษ์ที่ไม่มีอีเมลแสดงสถานะต้องตรวจสอบตัวตนก่อนแสดงคะแนนรวม
- อีเมลที่ไม่ได้รับมอบหมายไม่ถูกนำมาคิด และแจ้งรายการที่ถูกตัดออกให้ผู้จัดการตรวจ
- ตรวจคะแนนรวมกับคะแนนย่อย และตรวจเวอร์ชันเกณฑ์ รายการผิดหรือว่างไม่นับเป็นคะแนน 0
- แผนความก้าวหน้าที่แก้ภายหลังไม่เปลี่ยนคะแนนยืนยันเดิม การสรุปอ่านคะแนนยืนยันตามเดิม

## ใช้งาน

เข้าสู่ระบบ → ดูจำนวนข้อมูลครบ/ยังขาด → กรองด้วยชื่อ รหัส หัวข้อ ห้อง สถานะ หรือส่วนที่ยังไม่ครบ → เปิดรายละเอียดเพื่อดูรายชื่อผู้ประเมินและรายการที่ขาด

แถบความครบถ้วนรายส่วนกดเพื่อกรองนิสิตที่ยังไม่ครบได้ ตารางเปลี่ยนเป็นการ์ดบนมือถือและแท็บเล็ตจอเล็ก เรียงคะแนนรวมได้โดยรายการรอข้อมูลอยู่ท้ายเสมอ

CSV ดาวน์โหลดตามตัวกรองทุกหน้า มีคะแนนแต่ละส่วน จำนวนผู้ประเมินที่มี/ต้องครบ คะแนนรวม และสถานะ ช่องคะแนนที่ยังไม่มีและคะแนนรวมที่ยังไม่ครบเว้นว่าง แยกจากเลข 0 และป้องกันข้อความที่อาจถูกอ่านเป็นสูตร

หน้านี้และ API `getCourseSummary` **อ่านอย่างเดียว** ไม่สร้างชีท ไม่แก้ข้อมูลคะแนนต้นทาง กดรีเฟรชเพื่ออ่านคะแนนล่าสุด

## ทดสอบ

`npm test` ตรวจสิทธิ์ การเฉลี่ย/รวม ความครบถ้วน คะแนน 0 รายการซ้ำ ข้อมูลผิด และการคงข้อมูลต้นทาง

`npm run test:summary` ทดสอบ Chrome และ WebKit จำลองมือถือ รวมการเข้าสู่ระบบ ตัวกรอง รายละเอียด CSV แบ่งหน้า กราฟ ขนาด 320–1440 px การลองใหม่ และการล้างข้อมูลเมื่อเปลี่ยนบัญชี โดยใช้ข้อมูลจำลอง
